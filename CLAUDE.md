# CLAUDE.md

Ruby gem (>= 3.3) that wires Azure Workload Identity tokens into PostgreSQL connections — both raw `pg` and ActiveRecord. It mints federated tokens from `AZURE_*` env vars and supplies them as the connection password to Azure Database for PostgreSQL flexible server.

## Where things live

- [lib/pg/azure_workload_identity.rb](lib/pg/azure_workload_identity.rb) — entrypoint. Prepends [Connection](lib/pg/azure_workload_identity/connection.rb) onto `PG::Connection.singleton_class`, and (if `ActiveRecord` is defined) prepends [ActiveRecordPostgreSQLAdapter](lib/pg/azure_workload_identity/active_record_postgresql_adapter.rb) and [ActiveRecordPostgreSQLDatabaseTasks](lib/pg/azure_workload_identity/active_record_postgresql_database_tasks.rb).
- [auth_token_generator.rb](lib/pg/azure_workload_identity/auth_token_generator.rb) — calls Azure to mint tokens. The process-wide default is captured lazily via `PG::AzureWorkloadIdentity.auth_token_generator` so env-loaders (dotenv) can populate `ENV` before the generator reads it. **Do not eager-load it.**
- [auth_token.rb](lib/pg/azure_workload_identity/auth_token.rb), [auth_token_injector.rb](lib/pg/azure_workload_identity/auth_token_injector.rb) — token wrapper + the mechanism that swaps the token into the pending PG connection options.
- [connection_info/](lib/pg/azure_workload_identity/connection_info/) — parsers for the two `pg` connection-string syntaxes (`KeyValueString`, `URI`) plus an `ActiveRecordConfigurationHash` variant. All three normalize into the same shape the injector mutates.

Every `lib/**/*.rb` has a parallel `sig/**/*.rbs`. Update both together — Steep runs in CI.

## Tests

- `test/pg/**/test_*.rb` — unit tests, no Postgres needed. `bin/rake test:unit`.
- `test/acceptance/**` — hits a real Postgres via [docker-compose.test.yml](docker-compose.test.yml). `bin/rake test:acceptance`. CI uses a `postgres:18` service on port 25432.
- CI matrix-tests across Ruby × `pg` × `activerecord`; the matrix is generated by [bin/version-matrix](bin/version-matrix). Per-job version pinning is done via `PG_VERSION` / `ACTIVERECORD_VERSION` env vars consumed by the `Gemfile`.

## Common commands

| Task | Command |
|---|---|
| First-time setup | `bin/setup` — installs deps, RBS collection, and overcommit hooks |
| Default check (`rake default`) | `bin/rake` → unit + rubocop + rbs:validate + steep:check |
| Lint | `bin/rubocop` |
| Type check | `bin/rake rbs:validate && bin/steep check` |
| REPL | `bin/console` |

`BUNDLE_ONLY=default lint` gives a fast lint-only install (matches CI's lint job).

## Conventions

- `# frozen_string_literal: true` on every Ruby file; double-quoted strings (enforced by RuboCop).
- Patches use `prepend`, never `include` or `alias_method`.
- Pre-commit (overcommit) runs RuboCop + cheap built-ins only. RBS/Steep/tests are CI-only — too slow to gate every commit.
- Release notes are extracted per-version from [CHANGELOG.md](CHANGELOG.md) by `rake release:notes`. To cut a release: bump [version.rb](lib/pg/azure_workload_identity/version.rb), add a matching `## [x.y.z]` header to the changelog.
